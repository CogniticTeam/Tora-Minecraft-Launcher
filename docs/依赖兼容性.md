# XMCL 依赖兼容性

验证日期：2026-10-23。环境：macOS / Apple Silicon、Node.js 24.19.0、Java 21.0.12.1。

当前固定组合：

| 包 | 版本 | 原因 |
| --- | --- | --- |
| `@xmcl/core` | `2.16.2` | 使用版本解析、库规则判断、原生库解压和游戏进程启动 |
| `@xmcl/installer` | `6.1.2` | 已发布且可加载的 Task API，原版安装及 Fabric profile / 依赖安装 |
| `@xmcl/unzip` | override `2.1.2` | 避开 2.2.0 的 npm 发布元数据问题 |
| `undici` | `7.30.1` | 显式配置连接超时、并发、重试和重定向；通过全局 override 统一传递依赖 |

实际遇到的上游问题：

1. `@xmcl/unzip@2.2.0` 发布的 `package.json` 包含 `@xmcl/yauzl: workspace:^*`，npm 报 `EUNSUPPORTEDPROTOCOL`。即便覆盖该依赖，它的 `main` 仍指向未包含在 npm tarball 中的 `./index.ts`，运行时报 `MODULE_NOT_FOUND`。
2. `@xmcl/installer@6.3.6` 和 `6.3.5` 引用了 `@xmcl/core/utils`，但 `@xmcl/core@2.16.2` 的 npm 发布内容没有可加载的该子路径。实测 import 报 `Cannot find module '@xmcl/core/utils'`。
3. 因此当前使用 `6.1.2` 的 `installTask` / `installLibrariesTask` / `installFabricByLoaderArtifact`，不使用 6.3.x 的 InstallManifest API。此更改体现在 package.json 和 package-lock.json，未修改 node_modules 源码。
4. 安装器原先固定的旧版 Undici 在 npm audit 中存在已修复漏洞。根依赖固定 `7.30.1`，使用 `overrides.undici: "$undici"` 统一安装器、文件传输、用户认证和 Electron 下载工具的传递依赖。更新后 `npm audit --json` 返回漏洞总数 0。

安装进度直接读取 XMCL Task 的 `progress` / `total`（实际字节数）。依赖阶段切换后总量会变化，进度可能重新计算；安装完成前最多显示 99%，只有全部安装任务成功才显示 100%。取消调用 XMCL 的 Task.cancel，并终止尚未完成的元数据请求。已校验的文件保留用于重试。

默认下载器的 10 秒连接超时曾在本机下载客户端时失败。核心使用 45 秒连接超时、60 秒响应超时、8 个连接，保留 Undici 重试与重定向拦截器，避免不完整文件被当成成功。单个文件使用完整区间，文件间并行；不修改系统网络或代理设置。

当前实测：核心 5 项单元测试通过；Java 扫描找到 Homebrew Java 21；Mojang 官方版本清单返回 920 项；core / installer 的真实 Node.js import 成功。真实安装期间的取消测试通过，任务最终为 `cancelled`，实例保持 `installed: false`。Minecraft 1.21.1 原版及 Fabric 0.20.1 已完成安装、实际 Java 进程运行、渲染/声音初始化和退出码 0 验证；画面证据与未测边界见 [验证记录.md](./验证记录.md)。

Undici 7.30.1 升级后，用隔离目录的缓存重新执行原版与 Fabric 安装，两者均为 completed / 100%；另使用同一 Agent、重试与重定向配置通过 `@xmcl/file-transfer` 从官方下载 38408 字节的 1.21.1 版本描述并通过 SHA-1 校验，确认新的 dispatcher API 实际可用。该回归没有重新开启游戏窗口。

升级这些依赖时应重新检查 npm tarball、执行实际 import，然后验证原版和 Fabric 的完整安装与启动。避免仅依据安装命令成功判定依赖可用。
